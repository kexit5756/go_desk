## 三、每个文件的职责

```text
go_desk/
├── go.mod                     模块身份与依赖声明
├── go.sum                     依赖校验记录
├── makefile                   构建、运行、测试入口
├── main.go                    创建传输对象、启动监听、保持进程运行
└── p2p/
    ├── transport.go           定义节点与传输能力的接口
    ├── tcp_transport.go       TCP 监听、接收连接、Peer 封装
    └── tcp_transport_test.go  验证配置与监听启动
```

### main.go：把组件连接起来

入口调用 `p2p.NewTCPTransport(":3000")` 创建对象，然后调用 `ListenAndAccept()` 启动监听。启动失败时使用 `log.Fatal` 报告错误并结束程序。

末尾的 `select {}` 阻塞主 goroutine，避免 main 返回后整个进程退出。它目前承担保持服务运行的作用；系统信号处理与正常退出可以作为后续任务。

### transport.go：定义通信模块的边界

`Transport` 要求实现 `ListenAndAccept() error`。`*TcpTransport` 具有这个方法，因此自动满足接口，不需要显式声明实现关系。

`Peer` 当前没有任何方法，暂时只作为远程节点的抽象占位。空接口可以接收任意类型，不能据此调用连接的读写方法。

### tcp_transport.go：实现 TCP 接收连接的基础流程

| 类型或函数 | 当前职责 |
|---|---|
| TCPPeer | 保存 net.Conn 连接和 outbound 方向标记 |
| TcpTransport | 保存监听地址、监听器，以及预留的节点表与锁 |
| NewTCCPer | 创建 TCPPeer；函数名称有拼写问题，已标注 TODO |
| NewTCPTransport | 保存配置并返回指针，不在构造时监听端口 |
| ListenAndAccept | 调用 net.Listen，成功后启动后台循环 |
| acceptLoop | 阻塞等待连接，每次成功接收后启动处理 goroutine |
| handleConn | 创建 Peer 并打印日志，尚未读取或响应数据 |

需要区分：`net.Listener` 负责接收新连接，`net.Conn` 表示已经建立的一条连接。

### tcp_transport_test.go：验证最小启动能力

测试创建监听地址为 `:4000` 的对象，检查配置是否保存正确，并断言 `ListenAndAccept()` 返回 nil。

它验证的是“监听可以启动”，没有创建客户端，所以尚未验证连接接收、outbound 标记或消息收发。末尾关于端口占用的说明只是注释，并没有对应的测试函数。

### makefile：统一开发命令

```bash
make build   # 编译到 bin/fs
make run     # 先构建，再运行程序
make test    # 运行全部包的测试并显示详细输出
```

命令前的缩进必须使用真正的 Tab；`@` 表示执行时不回显该命令。`make run` 启动的服务可以用 Control+C 停止。

## 四、今天打通的执行链路

```text
make run
  ├─ go build -o bin/fs
  └─ ./bin/fs
       └─ main
            ├─ NewTCPTransport(":3000")
            ├─ ListenAndAccept
            │    ├─ net.Listen
            │    └─ go acceptLoop
            │         └─ Listener.Accept 等待连接
            │              └─ go handleConn(conn)
            │                   ├─ NewTCCPer(conn, true)
            │                   └─ 打印 Peer 信息
            └─ select {} 保持进程存活
```

图中的 `true` 是当前实际代码，存在入站连接方向标记不符的问题，见下方待完善项。

目前尚未实现 `net.Dial` 主动连接逻辑。讨论过 Dial 与 Accept 的区别，不代表两条路径都已编码完成。

## 五、当天解决和理解的问题

| 问题 | 原因或结论 |
|---|---|
| `make: missing separator` | Makefile 命令行曾使用空格缩进，已改为 Tab |
| `non-name t.Listener on left side of :=` | 结构体字段不能用于短变量声明，已有字段应使用 `=` 赋值 |
| `startAcceptLoop undefined` | 调用名称与定义的 `acceptLoop` 不一致，已统一 |
| 监听地址 `"4000"` 解析失败 | TCP 地址采用 host:port 形式，现有测试使用 `":4000"` |
| `[no test files]` | 只是说明该包没有测试文件，不是失败信息 |
| Go 模块路径 | go.mod 的 module 声明决定包导入前缀，与 Git 远程地址用途不同 |
| outbound 的意义 | 记录当前节点是否主动建立连接，不限制数据收发方向 |
| 终端操作 | 区分运行程序、使用 nc/telnet 连接、Control+C 停止以及清屏 |

## 六、当前待完善项

本次注释整理保留了原有有效代码；以下问题已写入注释或在本文说明，没有借补注释的机会改写业务逻辑。

| 优先级 | 当前观察 | 下一步建议 |
|---|---|---|
| 高 | handleConn 只从 Accept 路径进入，却使用 outbound=true | 入站连接应标记 false；后续 Dial 路径再使用 true |
| 高 | handleConn 结束后没有关闭连接，也没有将 Peer 交给其他组件管理 | 明确连接所有权和关闭时机，再加入读写处理 |
| 高 | 测试固定占用 4000 端口，结束时没有关闭监听器 | 使用 127.0.0.1:0，并在成功启动后添加 t.Cleanup |
| 中 | peers 是 nil map，mu 尚未实际使用 | 在需要登记节点时初始化 map，并明确加锁规则 |
| 中 | NewTCCPer 命名有拼写问题 | 统一重命名为 NewTCPPeer，并更新所有引用 |
| 中 | assert.Equal 的期望值与实际值顺序颠倒 | 改为 assert.Equal(t, listenAddr, tr.ListenAddress) |
| 中 | 检查 error 使用 assert.Nil | 后续可用 assert.NoError，让断言意图和错误信息更清楚 |
| 后续 | Peer 接口无方法，Transport 只有启动方法 | 随收发、关闭等需求逐步完善接口 |

当前注释特别说明了：声明 mutex 不会自动保护 map；空接口不约束具体能力；创建对象不等于监听启动；测试通过不等于消息通信已经完成。
